🔑 核心思想

分布式状态估计的隐私泄露点，恰恰是"融合必须靠通信"这一步：信息矩阵和信息向量一旦明文传输，等于把每个智能体的私有数据摊开给链路上的所有人。论文的思路是把"能不能算"和"能不能看见"解耦——用 Paillier 的加法同态性质，让智能体直接在密文上完成融合所需的加法和数乘；再配上一对编码/解码阶段（乘 $Q$ 取整、解密后除以 $Q$），把实数值搬进密码体制能处理的整数世界。Lemma 1 保证这趟"搬运"的误差随编码参数 $Q$ 增大而反比缩小——隐私不是拿估计精度硬换来的，这是下一节稳定性证明的地基。

2. 问题建模（一）：分布式状态估计与信息滤波框架

2.1 问题设定

论文研究的是一个分布式状态估计（distributed state estimation）问题：多个智能体通过各自的局部测量和邻居通信，共同估计一个动态系统的状态。单个智能体的测量是有限的——只靠自己估计不出来；所以必须与邻居交换信息，把各家掌握的"信息"拼起来用。

2.2 信息滤波（information filter）框架

整篇论文采用信息滤波的方法，每个智能体的每个时刻都走同一条四步流程：

  1. 预测：先根据上一时刻的估计做状态预测；
  2. 测量更新：利用当前时刻的局部测量完成测量更新，得到本地的信息矩阵 $\Omega$ 和信息向量 $q$；
  3. 信息交换与融合：与邻居交换信息，完成信息融合（论文采用的融合形式是 CI fusion，即交叉融合）；
  4. 后验估计：根据融合后的信息矩阵和信息向量，给出后验状态估计。

预测 ⟶ 测量更新（得到 $\Omega$、$q$）⟶ 邻居信息交换与融合（CI fusion）⟶ 后验状态估计

2.3 隐私问题的入口在第三步

请注意第 3 步：信息交换发生在邻居之间的通信链路上。也就是说，信息矩阵 $\Omega$ 与信息向量 $q$ 必须"出门"才能完成融合——这一步既是分布式估计成立的原因，也正是隐私问题的入口。

📝 现场观察：这是一个时变系统

分享过程中老师注意到，文中的 $A$ 与 $C$ 都带下标 $k$（$A_{k}$、$C_{k}$），也就是说文章讨论的是时变（time-varying）系统，不是定常系统。这一点会影响后面理论部分对系统参数的要求。

3. 问题建模（二）：隐私威胁从哪里来

3.1 威胁一：外部窃听者（external eavesdroppers）

如果信息矩阵和信息向量以明文形式在链路上传输，就很容易被外部窃听者直接截获——$\Omega$ 和 $q$ 本身就是各个智能体的私有数据，拿到明文等于拿到原始数据。

3.2 威胁二：内部诚实但好奇的节点（HBC）

即使链路安全，通信对象也未必"无害"：诚实但好奇（honest-but-curious, HBC）的节点会正常执行算法（不会主动破坏结果），但有的节点可能利用合法收到的信息，去推断其他节点的私有数值。这类威胁从内部来，靠"加密通信链路"本身是挡不住的。

威胁来源能力 / 手段直接后果
外部窃听者截获链路上明文传输的信息矩阵 / 信息向量私有数据被直接读取
内部 HBC 节点按算法正常收报与执行，额外利用收到信息做推断邻居的私有数值可能被推断出来

💡 直觉

分布式估计必须通信，而通信就必须"把数据交出去"。所以隐私保护不能靠不传（不传就没法融合），只能靠传了也看不见——这正是后面密码工具要解决的问题。

4. 论文的核心问题

把前两节合起来，论文要回答的问题可以写成一句话：

🔑 核心问题

如何在不暴露节点的原始信息矩阵和信息向量的情况下，完成正确的信息融合，同时保持分布式状态估计的有效性？

这句话里其实压着三个必须同时成立的要求：

  • 正确性：融合要算对——结果与明文融合一致；
  • 有效性：加密不能让估计性能塌掉，否则"安全的估计"没有意义；
  • 隐私性：原始信息矩阵与信息向量自始至终不出门。

三个要求的同时成立，才叫"隐私保护的分布式状态估计"。

5. 论文的两条主线

针对上面的核心问题，论文给出两条主线：

主线一 · 安全通信算法

利用 Paillier 密码体制的加法同态性质，设计一个安全通信算法；这个算法要能支撑隐私保护版的交叉融合——也就是让智能体在密文上完成融合所需的运算。

主线二 · 完整算法

把安全通信算法嵌进状态估计流程，形成一个完整的隐私保护分布式状态估计算法，同时应对外部窃听与内部好奇两类威胁。

6. Paillier 密码体制的两个基础性质

6.1 为什么需要它

信息矩阵与信息向量要参与融合运算，又不能明文传——那么有没有一种加密方式，能让"看不见明文"和"还能算"同时成立？论文选用的 Paillier 密码体制就具备这种能力：它是加法同态（additively homomorphic）的。

6.2 性质一：加法同态

$$\mathbf{E}(x) \cdot \mathbf{E}(y) = \mathbf{E}(x + y)$$

两个密文相乘，等于两个明文相加之后再加密

用分享里的话说：两个密文相乘，等于两个明文相加之后再加密。也就是说，"在密文上做乘法"对应"在明文上做加法"。

6.3 性质二：密文的幂运算

$$\mathbf{E}(x)^{2} = \mathbf{E}(2x)$$

密文的二次幂，等于明文的二倍再加密

用分享里的话说：密文的二次幂，等于密文的二倍再加密——也就是"密文的幂运算"对应"明文的数乘"。写成一般形式：

$$\mathbf{E}(x)^{k} = \mathbf{E}(kx)$$

6.4 两条性质合起来能做什么

$$\mathbf{E}(x)^{2} \cdot \mathbf{E}(y) = \mathbf{E}(2x) \cdot \mathbf{E}(y) = \mathbf{E}(2x + y)$$

先用幂运算完成数乘，再用乘法完成相加：我们虽然看的是密文，但可以在密文上做加法和数乘。分享里特别强调——这两条性质是后面所有计算的基础。

💡 直觉

隐私保护的关键不是"不计算"，而是"换个域计算"：明文上的加法与数乘，被搬到了密文上做——数据从头到尾没有被任何人看见。

7. 从实数到整数：编码-加密-解码回路

7.1 动机：Paillier 处理的是整数

密码体制的运算是建立在整数上的，而信息矩阵和信息向量都是实数。所以作者在加密之外，又加了编码（encoding）与解码（decoding）两个阶段，目的就是把实数变成整数再加密。

编码的核心是两件事：把数变成一个整数（取最接近的那个整数，即量化/取整），以及把符号信息保存好（sign preserved）。

7.2 回路三步：加密 → 解密 → 解码

第一步不是加密，而是编码——加密这一步只负责把编码好的整数藏起来，且要保住符号：

$$\Upsilon(s, r) = \operatorname{sgn}\big(\Gamma(s, r)\big)\, \mathbf{E}\big(|\Gamma(s, r)|\big)$$

式 (6) · 加密（sign preserved）：符号留在外面，只有绝对值进密码体制

加密时把符号单独提出来：$\operatorname{sgn}(\cdot)$ 留在外面，只把绝对值送进 $\mathbf{E}(\cdot)$ 加密——这样负号不会丢，这就是 sign preserved 的含义。

$$\Gamma(s, r) = \operatorname{sgn}\big(\Upsilon(s, r)\big)\, \mathbf{D}\big(|\Upsilon(s, r)|\big)$$

式 (7) · 解密：先解出绝对值，再按原符号拼回去

$$\widetilde{\Psi}(s, r) = \frac{\Gamma(s, r)}{Q}$$

式 (8) · 解码：divide by $Q$ to recover real values

解码动作很简单：除以编码参数 $Q$，把整数还原成实数。

7.3 编码参数 Q 的作用

$Q$ 是编码要用的参数：$Q$ 越大，量化越精细、误差越小。分享中预告了后面会给出一个精确的误差界——就是第 8 节的 Lemma 1。

7.4 一条完整的回路

编码（提符号、取整）⟶ 加密 ⟶ 密文上的加法与数乘（对几个加密量做统计与求和）⟶ 解密 ⟶ 解码（除以 $Q$）

分享里强调这条回路的意义：发送者把自己的数据加密后发出去，另一方在密文上做加运算后把结果发回去——中间任何一方都没有见过原始数据。

7.5 统一记号

$$\left\{ \begin{array}{l} \Gamma = \mathbf{E}_{\mathbf{N}}(\Psi, Q), \\ \Upsilon = \mathbf{E}_{\mathbf{M}}(\Gamma, Q) = \mathbf{E}_{\mathbf{M}}(\Psi, Q), \\ \widetilde{\Psi} = \mathbf{P}_{\mathbf{M}}(\Psi, Q). \end{array} \right.$$

记号含义（OCR 术语表）：$\mathbf{E}_{\mathbf{N}}$（EN） = encoding 编码；$\mathbf{E}_{\mathbf{M}}$（EM） = encryption 加密；$\mathbf{E}_{\mathbf{NM}}$（ENM） = encoding-encryption 编码-加密；$\mathbf{P}_{\mathbf{M}}$（PM） = full operation 完整操作（编码 → 加密 → 密文运算 → 解密 → 解码）。

读法：$\Gamma$ 是编码后的量；$\Upsilon$ 是加密后的量（也就是 $\mathbf{E}_{\mathbf{NM}}$ 作用的结果）；$\widetilde{\Psi}$ 是完整操作作用在原量 $\Psi$ 上的最终结果——可以理解为 $\Psi$ 走了一趟"加密通道"之后的近似版本。

💬 现场讨论：编码式子里的 $s$ 和 $r$ 是什么？

分享中有同学提问：式子 $\Upsilon(s, r)$、$\Gamma(s, r)$ 里的 $s$ 和 $r$ 分别指什么？讨论中确认：$s$ 就是被编码的那个数本身；随后有同学追问另一个符号是不是"精度 / 小数位数"之类的含义，现场没有展开。可以确定的是：$Q$（现场口语说的"欧"）是编码要用的参数，它的大小直接决定量化的精细度与误差界。至于 $r$，本次分享没有展开讨论——本节如实保留这个空白。

8. Lemma 1：编码-解码的量化误差界

编码会把实数"压"成整数，这必然带来误差。论文用 Lemma 1（量化误差界）把误差框住：

$$F - \frac{n}{2Q}I \;\leq\; \mathbf{P}_{\mathbf{M}}(F, Q) \;\leq\; F + \frac{n}{2Q}I$$

Lemma 1 · 编码-解码误差双侧有界，界宽 $n/(2Q)$

三个要点（OCR 原文）：

  • 误差被 $n/(2Q)$ 界住：编码-解码的误差有明确的界；
  • 双侧（two-sided）：既有下界、也有上界，不是"只保证不超"；
  • 与 $Q$ 成反比（inversely proportional）：$Q$ 越大，误差界越窄——这是后续稳定性证明的基础（the basis of the stability proof）。
符号含义
$F$待处理的量（信息向量或信息矩阵）
$\mathbf{P}_{\mathbf{M}}(F, Q)$完整操作作用在 $F$ 上的结果（编码 → 加密 → 密文运算 → 解密 → 解码）
$n$与量 $F$ 的维数有关的常数（原式中乘在单位矩阵 $I$ 上）
$Q$编码参数（越大越精细，误差越小）
$I$单位矩阵（说明误差界按分量给出）

💡 直觉

$Q$ 越大，$n/(2Q)$ 越小，$\mathbf{P}_{\mathbf{M}}(F, Q)$ 就越接近 $F$——"加密-解密"这层搬运对结果的影响可以被压得很小。所以隐私保护并不必然意味着估计精度"硬亏"：失真随 $Q$ 反比收缩，是可控的。

9. 安全通信算法：智能体 i 发出去什么

把同态性质与编码回路打包，论文给出了智能体之间安全通信的三步算法（OCR 帧 "What agent i sends"）：

Step 1

智能体 $i$ 选择一对合适的公钥 $P$、私钥 $S$，以及编码参数 $Q$。

Step 2

借助 $P$、$Q$，计算得到 $\mathbf{E}_{\mathbf{NM}}(\widetilde{\varphi}, Q)$ 与 $\mathbf{E}_{\mathbf{NM}}(\widetilde{\chi}, Q)$。

Step 3

把 $\mathbf{E}_{\mathbf{NM}}(\widetilde{\varphi}, Q)$、$\mathbf{E}_{\mathbf{NM}}(\widetilde{\chi}, Q)$、$Q$ 和 $P$ 一起发送给邻居 $j$（$j \in \mathcal{N}_{i}$，$j \neq i$）。

$$\mathbf{E}_{\mathbf{NM}}\big(\widetilde{\varphi}, Q\big), \qquad \mathbf{E}_{\mathbf{NM}}\big(\widetilde{\chi}, Q\big)$$

9.1 发出去的到底是什么

发出的内容说明（OCR）
信息向量的密文 $\mathbf{E}_{\mathbf{NM}}(\widetilde{\varphi}, Q)$ciphertext of information vector
信息矩阵的密文 $\mathbf{E}_{\mathbf{NM}}(\widetilde{\chi}, Q)$ciphertext of information matrix
编码参数 $Q$邻居做运算与解码时需要
公钥 $P$供邻居执行同态运算

🔑 留在本地的东西

私钥 $S$ 留在本地（the private key $S$ stays local）——解密必须用私钥，它不出门，密文才安全。另一个值得注意的设定是：每个智能体在每个时刻都生成一个不同的密钥对（every agent generates a distinct key pair at each time step），密钥不跨时刻复用。

📝 记法提醒

这里的 $P$、$S$ 分别是公钥（public key）与私钥（private key），不要与状态估计里的符号混淆；密文括号里的 $\widetilde{\varphi}$、$\widetilde{\chi}$ 分别对应信息向量与信息矩阵。

10. 小结

环节结论
问题多智能体靠各自的局部测量 + 邻居通信共同估计动态系统状态；信息滤波流程为：预测 → 测量更新（得 $\Omega$、$q$）→ 信息交换与融合 → 后验估计
威胁邻居交换阶段明文传输 → 外部窃听者直接截获；内部 HBC 节点可推断邻居的私有数值
核心问题不暴露原始信息矩阵 / 信息向量的前提下完成正确融合，并保持估计的有效性
密码工具Paillier 的加法同态 + 密文幂运算 → 密文上可做加法与数乘
编码回路编码（提符号、取最近整数）→ 加密 → 密文上的加法统计 → 解密 → 解码（除以 $Q$）
误差保证Lemma 1：误差界宽 $n/(2Q)$，与 $Q$ 成反比、双侧有界
安全通信三步算法：选 $P$ / $S$ / $Q$ → 算出 $\mathbf{E}_{\mathbf{NM}}(\widetilde{\varphi}, Q)$ 与 $\mathbf{E}_{\mathbf{NM}}(\widetilde{\chi}, Q)$ → 发密文 + $Q$ + $P$ 给邻居；$S$ 本地保留，每时刻换新密钥对

因为分布式状态估计中单个智能体的测量是有限的，必须与邻居交换信息才能完成融合——这一步信息矩阵和信息向量要"出门"。若以明文形式传输：(1) 外部窃听者可以直接截获明文，读到原始的 $\Omega$ 与 $q$；(2) 内部 HBC（诚实但好奇）节点虽然会正常执行算法，但可能利用合法收到的信息推断其他节点的私有数值。前者从链路来、后者从内部来，所以两类都要防。

练习2：只用密文算出 $\mathbf{E}(3x + 2y)$

已知加密 $\mathbf{E}(\cdot)$ 满足 $\mathbf{E}(x) \cdot \mathbf{E}(y) = \mathbf{E}(x + y)$ 与 $\mathbf{E}(x)^{k} = \mathbf{E}(kx)$。若要在不接触明文 $x$、$y$ 的前提下得到 $\mathbf{E}(3x + 2y)$，应怎样组合密文？

点击查看答案

$$\mathbf{E}(x)^{3} \cdot \mathbf{E}(y)^{2} = \mathbf{E}(3x) \cdot \mathbf{E}(2y) = \mathbf{E}(3x + 2y)$$

先各自用幂运算完成数乘（把 $x$ 变 $3x$、$y$ 变 $2y$），再用乘法完成相加。整个过程只用到密文——这就是"在密文上做加法和数乘"的用法。

练习3：编码参数 $Q$ 与误差界（数值）

设某个量的维数 $n = 4$。按 Lemma 1，当 $Q = 100$ 时误差界的宽度 $n/(2Q)$ 是多少？若把 $Q$ 提高到 $1000$，误差界变成多少？这说明了 $Q$ 的什么作用？

点击查看答案

$Q = 100$ 时：$n/(2Q) = 4/(2 \times 100) = 0.02$；$Q = 1000$ 时：$4/(2 \times 1000) = 0.002$——缩小到原来的十分之一。说明：(1) $Q$ 越大，量化越精细、误差界越窄；(2) 误差界与 $Q$ 成反比，所以只要 $Q$ 取得足够大，加密-解密-解码这层搬运的失真就可以被压到很小——这是"隐私保护不必以估计精度为代价"的关键。

练习4：三步算法里，什么出门、什么留下？

按安全通信算法的三步描述回答：(1) 智能体 $i$ 每个时刻会把哪些东西发给邻居？(2) 哪一个量必须留在本地、为什么？(3) "每个时刻生成不同的密钥对"这一设定说的是什么？

点击查看答案

(1) 发出去四样：信息向量的密文 $\mathbf{E}_{\mathbf{NM}}(\widetilde{\varphi}, Q)$、信息矩阵的密文 $\mathbf{E}_{\mathbf{NM}}(\widetilde{\chi}, Q)$、编码参数 $Q$、公钥 $P$。

(2) 私钥 $S$ 留在本地——解密要用私钥，它不出门，密文对邻居和窃听者才安全（论文原文：the private key S stays local）。

(3) 论文的设定是"每个智能体在每个时刻生成一个不同的密钥对"（distinct key pair at each time step），即密钥不跨时刻复用。
